## 💡 الفكرة

الحاج وسط زحام الملايين ما يحتاج تطبيق يشغله عن عبادته — يحتاج تطبيق **يشتغل عنه**.

ذكّر يعدّ أشواط الطواف والسعي **تلقائياً** بالـ GPS والبوصلة، ويعرض الدعاء المناسب **حسب مكانك** في الحرم، ويجاوب على أسئلة المناسك فوراً — حتى والشاشة مقفلة.

## ✨ المميزات

### للحاج والمعتمر
| الميزة | كيف تشتغل |
|--------|-----------|
| 🕋 **عدّاد الطواف التلقائي** | GPS + بوصلة مع فلتر Kalman — يعدّ الأشواط حول الكعبة بلا أي لمسة، ويتحقق من اتجاه الدوران (عكس عقارب الساعة) |
| 🚶 **عدّاد السعي التلقائي** | GPS + عدّاد خطوات + dead-reckoning — يميّز الوصول الفعلي للصفا والمروة حتى داخل المسعى المغطى |
| 📿 **أدعية حسب الموقع** | يعرض دعاء الطواف وأنت تطوف، ودعاء السعي وأنت تسعى — يتغير تلقائياً مع تنقلك بين مناطق الحرم |
| 🤖 **مساعد المناسك الذكي** | اسأل صوتاً أو كتابة عن أي حكم أو خطوة — يرد بالعربي مع نطق صوتي (TTS/STT) |
| 📖 **دليل المناسك** | شرح خطوة بخطوة لـ 9 مناسك + جدول أيام الحج (8–13 ذي الحجة) |
| 👨‍👩‍👧‍👦 **مجموعات العائلة** | كود `HAJJ-XXXX` يجمع عائلتك على خريطة واحدة — مشاركة الموقع بموافقة صريحة فقط |
| 🆘 **زر الطوارئ SOS** | إرسال موقعك فوراً عبر WhatsApp + إشعار مباشر لغرفة العمليات |
| 🔋 **ذكاء البطارية** | أعلى دقة GPS فقط داخل نطاق 120م من المطاف والمسعى — وضع توفير تلقائي في منى وعرفات والفندق |
| 📴 **يعمل والشاشة مقفلة** | خدمة أمامية (Foreground Service) تكمل عدّ الأشواط في جيبك |

### لغرفة العمليات (لوحة المشرف)
- 🗺️ **لوحة الزحام الحية** — خريطة حرارية متحركة لمناطق الحرم مع مؤشر LIVE
- 📢 **تنبيهات موجّهة** — إرسال تنبيه لمنطقة محددة (المطاف فقط، المسعى فقط...)
- 🚨 **مراقبة نداءات SOS** — استقبال ومتابعة وإغلاق الحالات
- 📍 **محرر مناطق تفاعلي** — رسم مناطق الحرم على الخريطة بنمط Google Maps

## 🏗️ البنية التقنية

```
Flutter (Dart) — واجهة واحدة لـ Android / iOS / Web
│
├── الموقع والحساسات
│     geolocator (bestForNavigation) · بوصلة · عدّاد خطوات
│     فلتر Kalman لتنعيم مسار GPS وسط تشويش المباني
│
├── Firebase
│     Firestore (أدعية · مناطق · مجموعات · تنبيهات فورية · SOS)
│     Hosting (نسخة الويب) · Crashlytics · قواعد أمان مشددة
│
└── المساعد الذكي
      Cloudflare Worker (proxy) → Groq LLM
      المفتاح السري محفوظ خادمياً — لا يلمس التطبيق أبداً
```

**قرارات تصميم أساسية:**
- **الخصوصية أولاً:** مشاركة الموقع في المجموعات اختيارية بالكامل (opt-in)، تُكتب كل 45 ثانية كحد أقصى، وقواعد Firestore تمنع أي قراءة من خارج أعضاء المجموعة
- **لا مفاتيح في الكود:** مفتاح الذكاء الاصطناعي في Cloudflare Worker Secret — العميل يتصل بالـ proxy فقط
- **دقة الأشواط قبل كل شيء:** العدّ لا يبدأ إلا بعد المرور الأول بنقطة البداية (تسليح العدّاد)، والدوران يُحتسب عكس عقارب الساعة فقط

## 🧠 المساعد الذكي — الإصدار المؤمّن (Secure, Grounded Assistant)

الوسيط (`assistant-proxy/worker.js`) أُعيد بناؤه ليتحقق من هوية المستخدم،
يحدّ الطلبات، ويعيد إجابة بصيغة JSON منظّمة قابلة للتحقّق بدل نص حر. راجع
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) للتفاصيل الكاملة والحدود
الموثّقة لكل قرار.

### متغيرات البيئة المطلوبة على الـ Worker (Cloudflare Settings → Variables)

| المتغيّر | الغرض |
|---|---|
| `GROQ_API_KEY` (سرّي) | مفتاح Groq — المزوّد الأساسي |
| `GEMINI_API_KEY` (سرّي، اختياري) | مفتاح Gemini — احتياطي عند فشل Groq |
| `FIREBASE_PROJECT_ID` | **مطلوب** للتحقق من `aud`/`iss` في Firebase ID Token. عند تفعيل المصادقة (الإنتاج أو `REQUIRE_AUTH=true`) يُرفض أي طلب بـ `503 ERR_SERVER_MISCONFIGURED` إذا كان فارغاً — لا يتم تخطّي التحقق من `aud`/`iss` أبداً بسبب غياب المتغيّر |
| `ALLOWED_ORIGINS` | نطاقات الويب المسموحة لـ CORS، مفصولة بفواصل (لا `*` في الإنتاج) |
| `ENVIRONMENT` | `production` يُفعّل: رفض بلا توكن، رفض أصل غير مسموح، منع fixtures التطوير |
| `REQUIRE_AUTH` | `true` لإجبار التحقق من الهوية في بيئة غير الإنتاج أيضاً |
| `FIRESTORE_PROJECT_ID` (اختياري) | لتفعيل استرجاع المصادر المعتمدة الحقيقي من `knowledge_chunks` |

لا تُحفظ أي قيمة فعلية داخل المستودع — هذه أسماء المتغيّرات فقط.

### تشغيل واختبار الوسيط محلياً

```bash
cd assistant-proxy
node --test worker.test.mjs   # أو: npm test
```

### قواعد Firestore الجديدة

أُضيفت في `firestore.rules`: `knowledge_documents` و`knowledge_chunks`
(قراءة لأي مسجّل، كتابة للأدمن فقط — العميل لا يمكنه توثيق محتوى نفسه)،
و`assistant_feedback` (اختياري، بدون نص المحادثة الكامل إلا بموافقة صريحة
على نفس الوثيقة). فهرس مركّب مطلوب لاحقاً على `knowledge_chunks`
(`keywords` array-contains-any + `language` equality) عند تفعيل الاسترجاع
الحقيقي عبر `FIRESTORE_PROJECT_ID`.

### منفّذ فعلياً مقابل توضيحي/مستقبلي (Implemented vs Demo vs Future)

- ✅ **مُنفّذ ومُختبر:** تأمين الوسيط (توكن Firebase، CORS، حدود الطلب،
  Rate limiting best-effort)، عقد استجابة JSON منظّم يُفرَض من الخادم
  (لا استشهادات مُختلَقة أبداً حتى لو خالف النموذج التعليمات)، بنية
  استرجاع (RAG) بحث بالكلمات المفتاحية على Firestore مع سلوك "لا أستطيع
  التحقق" الآمن عند عدم وجود نتائج، `PilgrimContext` موافقة صريحة موصول
  بعدّادات الطواف/السعي الفعلية (`AppCubit`) بلا تكرار حالة، شارات
  الاستشهاد/عدم الاتصال/التوجيه لمرشد بشري في الواجهة.
- 🧪 **توضيحي (Demo/Fixtures) بوضوح:** عيّنتا محتوى تطويري في الوسيط
  (`DEV_FIXTURE_DOCS`) — **غير دينيتين صراحةً** ومُعلَّمتان `[DEV FIXTURE]`
  في كل حقل، تُستخدمان فقط في بيئة غير الإنتاج لاختبار مسار
  الاسترجاع→الاستشهاد بدون أي محتوى ديني حقيقي أو مُختلَق.
- 🔜 **مستقبلي (غير منفَّذ في هذا التغيير):** محرك التوجيه الاستباقي
  الحتمي، لوحة إحصاءات الأدمن المجمّعة/المجهولة، تحديد موقع دقيق موصول
  فعلياً للمساعد (المنطقة المرسلة حالياً اسمية فقط من `ZoneModel`)، فهرسة
  محتوى ديني معتمد فعلي (لا تتوفر مصادر معتمدة رسمياً بعد).
